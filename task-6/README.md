# task-6 — Ревью и оптимизация кода автотестов (Ollama + AST)

Скрипт на Python 3, который:
1. **Анализирует** код автотестов (`bad_code.py`) — статический анализ на модуле `ast` собирает метрики и находки.
2. **Ревьюит код через LLM** — отправляет исходный код + AST-контекст в локальную модель Ollama (`qwen2.5-coder:7b`) для экспертной оценки: что хорошо, что плохо, рекомендации.
3. **Генерирует оптимизированный вариант** автотестов — LLM (Ollama) генерирует код на основе найденных проблем.
4. **Готовит отчёт** о ревью в формате Markdown (`review.md`) — включает секцию LLM-ревью и детализацию AST-метрик.

## Файлы

| Файл | Назначение |
| --- | --- |
| `review_and_optimize.py` | Основной скрипт: Ollama-ревью + AST-анализ + оптимизация + отчёт |
| `bad_code.py` | Исходный (намеренно «плохой») код автотестов |
| `optimized_code.py` | Сгенерированный оптимизированный вариант (результат работы скрипта) |
| `review.md` | Отчёт по ревью: LLM-оценка + сильные/слабые стороны (результат работы скрипта) |

## Запуск

```bash
python3 review_and_optimize.py
```

По умолчанию скрипт читает `bad_code.py`, пишет `optimized_code.py` и `review.md` в ту же
директорию. Пути и параметры Ollama можно передать аргументами:

```bash
python3 review_and_optimize.py --input bad_code.py --output optimized_code.py --report review.md \
    --ollama-host http://localhost:11434 --model qwen2.5-coder:7b
```

Параметры Ollama также читаются из переменных окружения:
- `OLLAMA_HOST` (по умолчанию `http://localhost:11434`)
- `OLLAMA_MODEL` (по умолчанию `qwen2.5-coder:7b`)

Зависимости: стандартная библиотека Python 3 + `requests` (используется и для HTTP-запросов
к тестируемому API, и для обращения к REST API Ollama). Дополнительная библиотека `ollama`
не требуется — скрипт работает через `requests` напрямую.

## Архитектура

```
bad_code.py ──► AST-анализ (метрики, находки)
                    │
                    ▼
              Ollama (LLM) ──► ревью (strengths/weaknesses/recommendations)
                    │
                    ▼
              Ollama (LLM) ──► оптимизированный код
                    │
                    ▼
          optimized_code.py + review.md
```

**Анализ (через AST):**
- дублирование тестов — по структурной сигнатуре тела (константы заменяются «местами»);
- HTTP-запросы без `timeout`;
- захардкоженный путь эндпоинта, повторяющийся в каждом запросе;
- ассерты без поясняющих сообщений;
- неиспользуемые импорты;
- непоследовательное/артефактное именование тестов.

**Ревью (через Ollama):**
- промпт с исходным кодом + AST-метриками + находками → JSON со strengths/weaknesses/assessment/recommendations;
- модель: `qwen2.5-coder:7b` (код-модель, хорошо подходит для анализа автотестов).

**Оптимизация (через Ollama):**
- промпт с кодом + списком проблем → оптимизированный Python-код;
- одинаковые по структуре тесты объединяются в один `@pytest.mark.parametrize`;
- добавляется фикстура `api_client` на базе `requests.Session` (пулинг соединений);
- во все запросы добавляется `timeout`;
- эндпоинты выносятся в константы;
- ассертам добавляются информативные сообщения.

> Дополнительно: если исходный файл не является валидным Python-кодом (например, пропущены
> отступы в телах функций — так и есть в `bad_code.py`), скрипт **автоматически восстанавливает
> синтаксис** и отмечает это в отчёте.

## Проверка результата

Сгенерированный код собирается и проходит (проверялось против локального тестового сервера
`POST /users`, эмулирующего 201/400):

```bash
python3 -m pytest optimized_code.py --collect-only -q   # 5 параметризованных случаев
python3 -m pytest optimized_code.py -v                  # 5 passed (нужен сервер на :8000)
```
